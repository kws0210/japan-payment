## 로그인·서버 기록

문자 인증·비밀번호 없이 전화번호만 입력하는 방식은 사용자가 선택한 요구사항이다.
번호를 아는 사람도 같은 기록을 조회·변경할 수 있다.
전화번호를 정규화한 SHA-256을 계정 식별자로 사용하며 원문 번호를 Firestore에 저장하지 않는다.
해시는 번호 소유자 인증이나 비밀번호를 대신하지 않는다.

브라우저는 로그인 정보를 유지하고, 설정·사용 횟수·일일 기록은 Firestore에서 불러온다.
Firestore Lite를 사용해 횟수를 브라우저 디스크에 별도 캐시하지 않는다.
로그아웃은 로그인 화면으로 돌아가며 서버 기록을 삭제하지 않는다.
같은 번호로 다시 로그인하거나 다른 기기에서 접속하면 기록을 복원한다.

설정은 `paymentAccounts/{계정}/preferences/current`, 일일 기록은 `paymentAccounts/{계정}/daily/{YYYY-MM-DD}`에 저장한다.
카운트·일일 기록·요청 기록을 트랜잭션으로 갱신하고 재시도로 같은 요청이 중복 반영되지 않게 한다.
오래된 설정 편집은 revision을 확인해 다른 기기의 최신 설정을 덮어쓰지 못하게 한다.
계정 전환 뒤 이전 요청의 응답을 새 계정 화면에 반영하지 않는다.

## 사용 횟수

| 기록 | 전체 한도 | 일일 제한·의미 |
| --- | --- | --- |
| 카카오페이 결제 할인 | 1회 | 돈키호테·간사이공항 결제 할인에 공통 사용한다. |
| KB 유니온페이 일반 10% | 3회 | 돈키호테 전용 행사와 별도다. |
| 돈키호테 500엔 즉시 할인 | 3회 | 일본 날짜 기준 하루 1회다. |
| 돈키호테 4,000엔 즉시 할인 | 3회 | 일본 날짜 기준 하루 1회이며 별도 사전 등록이 필요하다. |
| 돈키호테 매장 쿠폰 | 누적 기록 | 프로모션 전체 한도가 확인된 것은 아니다. 저장 검증 상한은 1,000,000이다. |

계산이 성공하면 실제 추천에 선택한 결제 혜택 하나와 매장 쿠폰의 횟수만 반영한다.
일반 결제만 추천하면 결제 할인 횟수는 늘리지 않는다.
이는 계산 기록이며 실제 승인·쿠폰 사용 여부를 외부에서 조회하는 기능은 아니다.
잘못 반영된 횟수는 확인 팝업이 있는 `+`·`−`로 조정한다.
0회에서 `−`, 각 상한에서 `+`를 비활성화한다.
돈키호테 전용 행사의 수동 조정은 오늘의 일일 사용 상태도 갱신한다.
설정 저장·점포 선택·로그아웃으로 횟수를 초기화하지 않는다.

## 장소와 추천 방식

상단 설정에 카드·쿠폰 보유와 사전 등록 상태를 저장하고 준비된 조합만 비교한다.
첫 설정을 저장하기 전에는 계산하지 않는다.
한 번의 결제에서 가능한 할인과 확인한 이용료를 비교하며 전체 여행의 미래 지출까지 최적화하지 않는다.

돈키호테를 선택하면 오사카 46개 지점을 검색·선택하는 팝업을 연다.
라디오로 임시 선택한 뒤 `확인`으로 적용하며 선택 전에는 확인 버튼을 비활성화한다.
`모름`은 임시 선택을 버리고 미확인 점포로 진행한다.
선택한 점포는 이번 거래에만 적용하고 계산·장소 변경·로그아웃 뒤 초기화한다.

공식 행사 목록과 대조한 오사카 대상 점포는 15곳이다.
해당 여부는 돈키호테 전용 500엔·4,000엔 후보에 적용한다.
다른 점포·미확인 점포도 일반 KB 10%와 보유 매장 쿠폰은 비교한다.
공항은 장소·금액으로 판단하고, 그 외 장소에서만 유니온페이 결제 가능 여부를 추가 확인한다.
점포 목록과 재조회 방법은 [점포 조사](../_japan-payment-firebase/OSAKA_STORES.md)에 있다.

카카오페이는 돈키호테 결제액 15,000엔 이상에서 보유 2,000엔 쿠폰, 간사이공항 10,000엔 이상에서 보유 1,200엔 쿠폰을 비교한다.
KB 일반 행사는 사전 등록한 카드로 건당 USD 50 이상일 때 10%, 최대 USD 20, 총 3회 조건을 반영한다.
최소 금액은 매장 쿠폰 적용 후 금액으로 판단한다.
KB 10%·돈키호테 500엔·4,000엔 즉시 할인은 합산하지 않고 가능한 것 중 하나를 선택한다.
매장 쿠폰과 결제 즉시할인은 서로 구분한다.
할인이 없으면 보유 트래블월렛을 우선하고, 없으면 보유한 카드·페이머니의 일반 결제를 안내한다.
사용 횟수가 소진된 결제 할인은 제외하며 수동 감소로 잔여 횟수가 생기면 다시 비교한다.

결과에는 엔 할인액·최초 입력액 대비 할인율·예상 결제액과 비교 근거를 표시한다.
돈키호테 입력액은 세금 제외 기준이며 면세액 자체를 추가 할인으로 합산하지 않는다.
매장 쿠폰을 사용하는 경우 결제 전에 점원에게 먼저 보여주도록 안내한다.
횟수·설정·일본 날짜가 바뀌면 이전 추천을 숨기고 재계산하도록 한다.

## 쿠폰 조사 결론

카카오 A+ 최대 7% 쿠폰과 UnionPay 전용 매장 쿠폰은 별개다.
별도 카카오페이 5% 쿠폰이 있다고 가정하지 않는다.
다른 일반 웹 쿠폰의 5%·7% 구간을 A+ 조건으로 옮기지 않는다.
A+는 확인한 구간 할인율을 설정에 저장하며 미확인 구간은 할인액에 합산하지 않는다.
UnionPay 전용 매장 쿠폰은 확인한 세금 제외 10,000~29,999엔 5%·30,000~49,999엔 7%를 사용하며 그 밖의 구간은 추정하지 않는다.

A+ 약관은 알리페이 제공 프로모션과의 중복을 허용하지만, 현재 2,000엔 쿠폰 쪽의 전체 약관은 확보하지 못했다.
따라서 최대 7%와 2,000엔은 각각 비교하고 합산하지 않는다.
이는 중복 불가를 확정한 판단이 아니다.
이용자에게 중복 가능 여부를 확인하라고 맡기는 설정은 제거했다.
기존 `kakaoStackConfirmed`·`unionDonkiEligible` 값은 추천에서 무시한다.
공식 행사·후기·실제 화면과 각 근거의 한계는 [쿠폰 조사](../_japan-payment-firebase/COUPON_EVIDENCE.md)에 있다.

카카오페이 앱 결제 링크는 <https://link.kakaopay.com/p/payment>다.
일본·Alipay+·페이머니나 정확한 A+ 쿠폰을 자동 지정하는 공개 링크는 확인하지 못했다.
실제 앱에서 일본·페이머니를 확인하는 경로를 가이드의 화면 10장으로 안내한다.
준비 가이드는 기본 닫힌 8개 작업만 보여주며 긴 조사 근거는 별도 근거 페이지에 둔다.

## 수수료와 환율

카드 비교는 KB 노리 체크(UnionPay) 예시 상품과 트래블월렛 엔화 잔액 결제 기준이다.
트래블로그 가정은 사용자 정정으로 폐기했다.
수수료·실결제 환율 직접 입력란은 제거하고 확인한 비용을 자동 반영한다.

| 수단 | 반영 방식 | 확인 한계 |
| --- | --- | --- |
| KB 노리 체크(UnionPay) | 할인 후 결제액의 예상 이용료 0.25~1.05%를 표시하고 순위에는 1.05%를 한 번 차감한다. | 공식 상품표·일반 안내의 요율이 다르며 이 범위가 전체 환전 비용의 확정 상한은 아니다. |
| 트래블월렛 | 엔화 충전·해외 가맹점 결제의 추가 수수료 0%를 반영한다. | 실제 원화 지출은 충전 당시 환율에 따라 달라진다. ATM·다른 통화·잔액 환불에 일반화하지 않는다. |
| 카카오페이 | 앱 환율 포함 비용을 미확인 `null`로 유지한다. | 공개 고정 요율·실결제 환율 API를 확인하지 못했으며 카카오 후보가 포함된 순위는 잠정 비교다. |

결제수단별 실제 청구·충전 환율 차이는 미반영이며 확정 원화 총지출을 만들어내지 않는다.
공식 수수료 출처와 불일치는 [비용 조사](../_japan-payment-firebase/FEES.md)에 보존한다.

50달러 조건은 자동 조회 USD/JPY 참고 환율로 판단한다.
진행 중인 환율 요청이 있으면 계산이 기다리고, 없거나 자동값이 30분 이상 지났으면 갱신한다.
Frankfurter를 먼저 조회하며 실패·6초 지연 시 ExchangeRate-API로 재시도한다.
제공처·기준일을 표시하고 응답의 기준일이 7일을 초과하면 거부한다.
둘 다 실패하고 유효한 기존 값도 없으면 입력·횟수를 보존하고 재시도나 직접 입력을 안내한다.
환율 직접 입력은 통신 실패 대비 수단이며 제거한 수수료 입력란과 별개다.
직접 입력과 로그아웃이 진행 중인 자동 조회보다 우선한다.
참고 USD/JPY·KRW를 카드 청구나 트래블월렛 충전의 실제 환율로 대체하지 않는다.
